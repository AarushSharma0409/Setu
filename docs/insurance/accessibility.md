# Insurance accessibility

Customer pages use headings, landmarks, visible labels, fieldsets/legends, status roles, button pressed states, and accessible progress labels. Required answers have adjacent error text and the wizard preserves entered values after a failed save.

The assessment uses native inputs where appropriate and touch-sized choice controls. Consent and disclosure actions are explicit and are not encoded by colour alone. Reduced motion is respected by shared UI styles.

Manual keyboard, zoom, and screen-reader validation still needs a running local API and browser session.
